# Weekly trading task contract (not integrated into the evolution loop)

`task.py` validates and copies one historical package, and scores selections in the trusted control environment. Candidate input is weekly-series-v1: 50 anonymous series containing all prior completed weeks, never current-week values. Candidate output is a JSON list of distinct anonymous indices 0..49, or [] for cash. The trusted scorer maps these indices to the target week's daily returns and applies 5 bps per side by default to strategy and 50-name benchmark, with daily rebalancing and weekly compounding. Score is weekly net excess return. The selection ordering must use exactly the package's permutation. Input features must independently be verified causal. Schema validation cannot prove causality.

This is a task contract only: `generate_loop.py` has an explicit domain allowlist, `utils/domain_utils.py` has domain-specific mappings, and `domains/harness.py` and `domains/report.py` implement fixed existing domain data/score behavior. No adapter or driver currently connects this contract to HyperAgents' archive, generation, or feedback; no prompts, objective, mutation code or existing loop have been changed.

Target execution configuration: an ephemeral GitHub-hosted runner with only an explicitly selected historical package and candidate code; no raw data, no data-store token, model key or GitHub token in candidate environment. Disable network, mount a fresh isolated filesystem, limit CPU, memory, processes, output and time, terminate all child processes and delete the filesystem after completion. Runner ephemerality alone is not a sandbox. Provision and adversarially test a genuine isolation boundary before executing untrusted code. Trusted data assembly and scoring must occur separately, never in the candidate container or on its runner; return only the selection. A runner workflow and secure retrieval protocol are not implemented.

Public repository: never add datasets, secrets, or confidential outputs here. A separate private data repository with LFS is the intended store, subject to LFS capacity and Databento licensing. Do not give the runner a credential for it. Package handoff authentication, integrity, replay protection, and feedback/archive synchronization still need design and verification.

## Session proxy scorer (28-name research universe)
`session_score.py` is a trusted-host-only scorer for the 28-name session-proxy data. It reconstructs the existing package permutation from the seed and calendar week index, reads the first and last available in-session minute-bar prices, checks each timestamp against the XNAS exchange calendar and requires all 28 names for every session. Partial boundary weeks, missing name-days, duplicate rows, and invalid values fail closed. Prices are proxies, not confirmed opening/closing auction fills; survivorship, price-quality, corporate-action and execution assumptions remain research limitations. It is not connected to any candidate, protected host or HyperAgents. The target-week scorer reports all three returns; the single-feedback channel does not yet exist. The earlier 50-name task validator is not compatible with 28-name packages. Do not use the scorer to claim a 50-name result.

Test: `SESSION_BARS=/path/to/proxy.parquet python3 domains/weekly_trading/test_session_score.py`. Requires duckdb and exchange_calendars. Never commit the parquet or data files here.
